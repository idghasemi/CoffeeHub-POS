# راهنمای استقرار CoffeeHub

## ساختار

- فرانت‌اند: `frontend`
- بک‌اند: `backend`
- نقطهٔ ورود FastAPI: `main:app`

## متغیرهای محیطی

فایل `.env.example` را بررسی و یک `.env` محلی بسازید. هیچ فایل `.env` واقعی را commit یا برای دیگران ارسال نکنید.

حداقل مواردی که باید در production کنترل شوند:

- secret امضای توکن با حداقل 32 بایت تصادفی
- مسیر پایدار دیتابیس و پوشهٔ backup
- origin مجاز فرانت‌اند
- حالت production و غیرفعال بودن debug
- secure cookie در استقرار HTTPS، اگر برنامه از cookie استفاده می‌کند

نمونهٔ ساخت secret:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## Reverse proxy

API را روی `127.0.0.1:8000` اجرا کنید و فقط reverse proxy را در دسترس شبکه قرار دهید. HTTPS، محدودیت حجم آپلود، timeout و headerهای امنیتی را در proxy تنظیم کنید.

## SQLite

- تنها یک پردازهٔ worker برای API اجرا شود.
- فایل دیتابیس روی filesystem محلی پایدار قرار گیرد، نه share شبکه‌ای نامطمئن.
- WAL/SHM را هنگام روشن بودن سرویس به‌صورت دستی کپی نکنید؛ از صفحهٔ backup استفاده کنید.
- هنگام Restore، فروش جدید ثبت نکنید.

## ارتقا

1. backup بگیرید.
2. نسخهٔ جدید را در پوشهٔ جدا استخراج کنید.
3. وابستگی‌ها را نصب و `scripts/verify-linux.sh` را اجرا کنید.
4. سرویس قبلی را متوقف کنید.
5. `.env` و مسیر دیتابیس را به نسخهٔ جدید متصل کنید.
6. سرویس را اجرا و ورود، فروش آزمایشی و گزارش را بررسی کنید.

## نگهداری

- backup روزانه و یک نسخهٔ خارج از دستگاه اصلی نگهداری شود.
- حداقل ماهانه restore آزمایشی روی محیط جدا انجام شود.
- فضای دیسک، خطاهای API، شکست ورود و عملیات backup پایش شوند.
